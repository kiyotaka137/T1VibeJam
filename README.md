# 🧠 RAG Task Service

Микросервис для генерации алгоритмических задач, умного поиска и контекстных подсказок.
Использует **FastAPI**, **LangChain**, **PostgreSQL (pgvector)** и **LLM** (совместимые с OpenAI API).

-----

## ✨ Возможности

1.  **Генерация задач (AI Generation):** Создание полноценной задачи (условие, код, тесты) по указанной теме и уровню сложности.
2.  **Оформление задач HR (Refinement):** Преобразование "сырого" текста условия от HR в структурированный JSON с авто-генерацией тестов и шаблонов кода.
3.  **Гибридное хранение:**
      * **SQL (PostgreSQL):** Хранит полную структуру задачи, скрытые тесты и историю чата.
      * **Vector (PGVector):** Хранит семантические эмбеддинги для умного поиска.
4.  **Умный поиск:** Поиск задач по смыслу (например, запрос "сортировка" найдет "Merge Sort").
5.  **Контекстные подсказки (Hints):** Чат-бот (Ментор), который помнит историю переписки по конкретной задаче и дает наводящие подсказки, не решая задачу за пользователя.

-----

## 🛠 Технологический стек

  * **Язык:** Python 3.10+
  * **API:** FastAPI
  * **LLM Orchestration:** LangChain
  * **Database:** PostgreSQL 15+
  * **Vector Extension:** pgvector
  * **Drivers:** `asyncpg` (асинхронный), `psycopg` (синхронный для LangChain), `sqlalchemy`.

## 🔌 API Documentation (Integration Guide)

### 1\. Генерация задач (`POST /generate_task`)

Автоматически генерирует задачу по указанной теме, используя "умную" модель-кодера.

  * **URL:** `/generate_task`
  * **Метод:** `POST`
  * **Действия (Side Effects):**
    1.  Генерирует условие, код и тесты через LLM.
    2.  Сохраняет **полную запись** в SQL таблицу (`tasks_{level}`).
    3.  Сохраняет **эмбеддинг описания** в Vector DB (pgvector) для поиска.

#### Request Body

```json
{
  "level": "junior",         // "junior" | "middle" | "senior"
  "topic": "Binary Search"   // Любая тема (строка)
}
```

#### Response (200 OK)

```json
{
  "task_id": "f73a95f9-0350-4b5d-84f7-517945fce8b5",
  "task_data": {
    "title": "Бинарный поиск",
    "description": "Напишите функцию...",
    "input_description": "Массив nums...",
    "output_description": "Индекс элемента...",
    "initial_code_python": "def search(nums, target): pass",
    "initial_code_cpp": "class Solution { ... }",
    "test_cases": [
      {
        "input": "[1,2,3], 2", 
        "output": "1"
      }
    ],
    "constraints": ["1 <= nums.length <= 100"]
  },
  "message": "Success"
}
```

-----

### 2\. Создание задачи от HR (`POST /create_custom_task`)

Принимает "сырой" текст от человека, "причесывает" его через LLM до стандарта (добавляет тесты, форматирует условие) и сохраняет.

  * **URL:** `/create_custom_task`
  * **Метод:** `POST`
  * **Действия (Side Effects):**
    1.  LLM форматирует текст, дописывает недостающие тесты и шаблоны кода.
    2.  Сохраняет результат в SQL таблицу (`tasks_{level}`).
    3.  Сохраняет эмбеддинг в Vector DB (pgvector).

#### Request Body

```json
{
  "level": "middle",
  "raw_text": "Задача про палиндромы. Дана строка s, верните true, если это палиндром. Пример: aba -> true."
}
```

#### Response (200 OK)

Возвращает такую же структуру, как `/generate_task` (см. выше), но с данными, извлеченными из текста HR.

-----

### 3\. Поиск задач (`POST /search_tasks`)

Ищет задачи по смыслу (семантический поиск). Запрос "сортировка" найдет задачи про "Merge Sort", "Quick Sort" и т.д.

  * **URL:** `/search_tasks`
  * **Метод:** `POST`
  * **Действия (Side Effects):** Читает из Vector DB (pgvector). Не изменяет данные.

#### Request Body

```json
{
  "query": "сортировка массивов", // Поисковая фраза
  "level": "junior",              // Уровень поиска
  "limit": 5                      // (Опционально) Кол-во результатов, по умолчанию 5
}
```

#### Response (200 OK)

Список найденных превью. Полную информацию нужно запрашивать отдельно по `task_id`.

```json
[
  {
    "task_id": "b59f599c-ec32...",
    "title": "Реализация сортировки слиянием",
    "preview": "Реализуйте алгоритм..." // Первые 200 символов описания
  },
  {
    "task_id": "6f507560-097c...",
    "title": "Слияние двух массивов",
    "preview": "Даны два отсортированных..."
  }
]
```

-----

### 4\. Получение полной задачи (`GET /task/{task_id}`)

Возвращает **всё**, что есть в базе по этой задаче (включая историю чата). Используется фронтендом для открытия страницы задачи.

  * **URL:** `/task/{task_id}`
  * **Метод:** `GET`
  * **Действия (Side Effects):** Читает из SQL таблицы.

#### Response (200 OK)

```json
{
  "task_id": "...",
  "title": "...",
  "description": "...",
  "input_description": "...",
  "output_description": "...",
  "constraints": ["..."],
  "function_name": "merge_sort",
  "initial_code_python": "...",
  "initial_code_cpp": "...",
  "test_cases": [...],
  "chat_history": [
    {"role": "user", "content": "..."},
    {"role": "assistant", "content": "..."}
  ],
  "hints": ["Подсказка 1", "Подсказка 2"],
  "level": "junior"
}
```

-----

### 5\. Генерация подсказки (`POST /hint`)

Анализирует код пользователя и историю переписки, чтобы дать контекстный совет.

  * **URL:** `/hint`
  * **Метод:** `POST`
  * **Действия (Side Effects):**
    1.  Читает текущую историю из SQL.
    2.  Генерирует ответ через LLM.
    3.  **Обновляет** историю чата и список подсказок в SQL таблице.

#### Request Body

```json
{
  "task_id": "f73a95f9-0350...",       // ID задачи, которую решает юзер
  "user_code": "def solve(): pass",    // Текущий код в редакторе
  "user_message": "Я не понимаю, как разделить массив." // Вопрос юзера
}
```

#### Response (200 OK)

```json
{
  "hint": "В этой задаче делить массив не нужно, так как..." // Текст ответа ментора
}
```

-----

### 6\. Получение тестов (`GET /tests/{task_id}`)

Технический эндпоинт для сервиса проверки решений (Checker). Возвращает только тесты.

  * **URL:** `/tests/{task_id}`
  * **Метод:** `GET`
  * **Действия (Side Effects):** Читает из SQL таблицы.

#### Response (200 OK)

```json
{
  "task_id": "...",
  "tests": [
    {
      "input": "[1, 2, 3]", // Аргументы для функции
      "output": "[1, 2, 3]" // Ожидаемый результат
    },
    {
      "input": "[]",
      "output": "[]"
    }
  ]
}
```

## 🗄 Структура Базы Данных

Сервис использует **PostgreSQL** с расширением `pgvector`.
Данные физически разделены на 3 таблицы по уровням сложности, чтобы ускорить поиск и разделить контексты:

1.  `tasks_junior`
2.  `tasks_middle`
3.  `tasks_senior`

> **Важно:** Все три таблицы имеют идентичную схему. Ключом является `task_id` (UUID string), который уникален в рамках всей системы.

### 📋 Схема таблицы (Columns)

| Название колонки | Тип (SQL) | Описание и назначение |
| :--- | :--- | :--- |
| **`task_id`** | `TEXT` (PK) | Уникальный идентификатор задачи (UUID). Используется во всех API запросах. |
| **`title`** | `TEXT` | Заголовок задачи (например, "Merge Sort"). |
| **`description`** | `TEXT` | Полное условие задачи (Markdown/Text). |
| **`input_description`** | `TEXT` | Описание входных данных (для человека). |
| **`output_description`** | `TEXT` | Описание выходных данных (для человека). |
| **`initial_code_python`** | `TEXT` | Шаблон кода (заглушка) для Python. |
| **`initial_code_cpp`** | `TEXT` | Шаблон кода (заглушка) для C++. |
| **`function_name`** | `TEXT` | Имя функции, которую должен реализовать пользователь (snake\_case). |
| **`constraints`** | `JSONB` | Список ограничений (время, память, диапазоны чисел). |
| **`test_cases`** | `JSONB` | **Скрытые тесты** для проверки решения (Input/Output). |
| **`chat_history`** | `JSONB` | История переписки с ментором по этой задаче. |
| **`hints`** | `JSONB` | Список уже выданных подсказок. |
| `created_at` | `TIMESTAMP` | Дата создания задачи. |

-----

### 🔍 Детальный разбор JSON-полей

Самые важные данные хранятся в формате JSONB. Вот как их правильно парсить.

#### 1\. `test_cases` (Для Чекера)

Используется сервисом проверки кода. Это массив объектов.

  * **input**: Строка или JSON-строка, содержащая аргументы функции.
  * **output**: Строка или JSON-строка, содержащая ожидаемый результат.

<!-- end list -->

```json
[
  {
    "input": "[1, 2, 3], 6",
    "output": "2"
  },
  {
    "input": "[], 0",
    "output": "-1"
  }
]
```

> **Как использовать:** При проверке решения подавайте `input` в функцию пользователя и сравнивайте результат с `output`.

#### 2\. `constraints` (Для Фронтенда)

Массив строк. Каждая строка — отдельное ограничение, которое нужно вывести пользователю списком.

```json
[
  "1 <= nums.length <= 10^4",
  "-10^9 <= nums[i] <= 10^9",
  "Алгоритм должен работать за O(log n)"
]
```

#### 3\. `chat_history` (Для Чата)

Массив сообщений в формате OpenAI. Хранит контекст общения пользователя с AI-ментором.

```json
[
  {
    "role": "user",
    "content": "Как мне найти середину массива?"
  },
  {
    "role": "assistant",
    "content": "Используйте формулу mid = left + (right - left) / 2, чтобы избежать переполнения."
  }
]
```

> **Как использовать:** Фронтенд может отрисовывать этот массив как историю переписки. При запросе новой подсказки (`POST /hint`) сервис сам обновит это поле.

### 🔗 Взаимодействие (Data Flow)

1.  **Поиск по смыслу:**

      * Вы делаете запрос к API `/search_tasks`.
      * API ищет вектора в `pgvector` индексе.
      * Возвращает `task_id` и превью.

2.  **Получение контента:**

      * Имея `task_id`, фронтенд запрашивает `/task/{task_id}`.
      * Сервис делает `SELECT * FROM tasks_{level} WHERE task_id = ...`.
      * Вы получаете полный JSON со всеми полями выше.

3.  **Проверка решения:**

      * Чекер запрашивает `/tests/{task_id}`.
      * Сервис делает `SELECT test_cases FROM ...`.
      * Вы получаете чистый список тестов для прогона.
